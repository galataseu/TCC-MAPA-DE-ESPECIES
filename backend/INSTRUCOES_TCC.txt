# TCC - Mapa de Espécies Ameaçadas
Este documento contém as instruções para executar e testar ambos os backends (Node.js e Django).

---

## 1. BACKEND NODE.JS (Express + Prisma)
Local: Raiz do projeto

### Comandos Principais:
- Instalar dependências: `npm install`
- Resetar Banco e Criar Usuários: `npm run prisma:seed`
- Iniciar em Desenvolvimento: `npm run dev`
- Rodar Testes: `npm test`

### Usuários Padrão:
### Usuários Padrão:
- **Admin:** admin / admin
- **User:**  user / user

---

## 2. BACKEND DJANGO (Django REST Framework)
Local: Pasta `/TCC-Django`

### Comandos Principais:
1. **Ativar Ambiente Virtual (OBRIGATÓRIO):** 
   `source venv/bin/activate`
   *(Após ativar, o comando `python3` usará o Django instalado no ambiente)*

2. **Instalar Dependências (se necessário):** 
   `pip install -r requirements.txt`

3. **Resetar Banco e Criar Usuários:** 
   `python3 manage.py reset_db && echo "from api.models import User; User.objects.create_superuser('admin', 'admin@example.com', 'admin', role='admin'); User.objects.create_user('user', 'user@example.com', 'user', role='user')" | python3 manage.py shell`

4. **Iniciar Servidor:** 
   `python3 manage.py runserver 8000`

*Dica: Se não quiser ativar o ambiente toda vez, você pode usar o caminho direto: `./venv/bin/python3 manage.py runserver 8000`*

### Admin Django (Painel Visual):
- Acesse: `http://localhost:8000/admin/`
- Login: admin / admin

---

## 3. DIFERENÇAS TÉCNICAS (Para o TCC)
- **Node.js:** Focado em performance assíncrona, usa Prisma ORM para consultas rápidas. Ideal para integrações em tempo real.
- **Django:** Focado em "baterias inclusas", já possui um painel administrativo pronto e uma estrutura de segurança muito robusta nativa.

---

## 4. RESOLUÇÃO DO "PROBLEMA" DOS IDS
Ambos os sistemas agora possuem comandos de "Seed/Reset" que:
1. Apagam todos os dados.
2. Reiniciam a contagem dos IDs (PK) de volta para o número 1.
3. Criam os usuários base para você não precisar criar manualmente toda vez.
